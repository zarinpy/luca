# Luca

Server-rendered application using FastAPI, Mako, and SQLAlchemy.
Typer is the command interface. Configuration comes from environment
variables and `.env` through pydantic-settings. Schema changes are Alembic
revisions generated by comparing the models with the database.

## Setup

```bash
python -m venv .venv
.venv/bin/pip install -e '.[dev]'
cp .env.example .env
```

`DB_URI` is a synchronous SQLAlchemy URL:

```text
postgresql+psycopg://:@/luca
```

An empty user and host use the local PostgreSQL account. Set a full URL
when the database expects a password.

## Commands

```bash
luca db create
luca db revision -m "init"
luca db upgrade
luca db basedata insert
luca db mockup insert
luca serve
```

`luca db rebuild` drops the configured database, creates it, applies
migrations, and inserts base data and mockup data.

`luca db revision -m "..."` writes a migration only when Alembic detects a
model change. Import new model modules from `luca/models.py` first.
`luca db revision -m "..." --empty` writes a blank revision for data changes
that autogenerate cannot see.

## Base data and mockup

`luca/basedata.py` calls each feature package's `basedata.insert(db)`.
`luca/mockup.py` does the same for sample data. A feature session is the
sync `db.session()` context manager. Base data is required application data.
Mockup data is sample data.
